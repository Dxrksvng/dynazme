# Contributing

> Short, honest answer first: external code contributions are not being accepted yet.

---

## Why not yet

Dynazme is in customer-discovery and pre-revenue phase. The implementation source is private, the surface area is small, and the founder's bandwidth is best spent on customer conversations rather than reviewing community pull requests.

Accepting contributions now would either be tokenistic ("thanks, we'll consider it" with no real path) or genuinely costly (review time pulled away from paying-customer work). Either is dishonest. So we wait.

---

## What you can do today

- **Open an issue** with a problem report — vagueness is fine; we'd rather hear "the architecture diagram is unclear" than nothing.
- **Open an issue** with a question about positioning, fit, or product scope.
- **Open an issue** sharing your business context if you think Dynazme might be useful — this is the most valuable contribution at this stage.
- **Send PR-sized typo fixes or doc-clarification patches** to the public README and supporting docs. These are accepted gladly.
- **Report security findings** via [`SECURITY.md`](./SECURITY.md), not via PR.

---

## What contributions look like later

When the project moves to Phase 2+ and starts publishing reusable code:

- Code contributions to clearly-marked open-source modules will be welcomed.
- A CLA (contributor licence agreement) will likely be required, given the dual public/private structure.
- Community contributions to non-customer-coupled documentation, examples, and integration adapters are most likely to land first.

This document will be updated when that transition happens.

---

## Code of conduct

Be civil, be specific, don't be a jerk. Founder reserves the right to close discussions that aren't moving anything forward. There is no formal code-of-conduct file at this stage; one will be added when the contributor base grows beyond the founder.
